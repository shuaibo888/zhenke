# 赛事系统单点登录开发要求

赛事系统需要支持用户从赛事系统免登录进入商城。双方以手机号判断是否为同一个用户。

赛事系统只需完成以下两个接口。

## 1. 签发一次性登录票据

当前用户点击“进入商城”时，赛事系统根据当前登录用户生成一次性票据，手机号必须从当前登录信息获取，不能接收前端传入的手机号。

```http
POST /api/sso/mall/tickets
Authorization: Bearer <赛事系统用户登录Token>
```

建议响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "ticket": "随机一次性票据",
    "expiresIn": 120,
    "redirectUrl": "https://dzshop.vip/sso/callback?ticket=随机一次性票据"
  }
}
```

也可以由赛事系统后端生成票据后直接通过 HTTP 302 跳转商城。

票据必须使用安全随机字符串，与当前用户手机号关联，有效期为 120 秒，并且只能成功使用一次。票据中不得直接包含手机号或用户登录 Token。

## 2. 验证并核销登录票据

该接口只供商城后端调用。验证成功后核销票据，并返回对应用户的手机号和用户昵称。

```http
POST /api/open/sso/mall/tickets/exchange
Authorization: Bearer <双方约定的服务端密钥>
Content-Type: application/json
```

请求：

```json
{
  "ticket": "一次性登录票据"
}
```

成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "phone": "13800138000",
    "username": "张三"
  }
}
```

返回字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `phone` | string | 是 | 当前赛事用户的完整手机号，商城以此判断是否为同一个用户 |
| `username` | string | 是 | 当前赛事用户的昵称，作用于商城的`nick_name` |

处理要求：

- 校验商城后端携带的服务端密钥。
- 校验票据存在、未过期且未使用。
- 成功响应与票据核销必须原子完成。
- 同一票据在并发请求下也只能成功一次。
- 票据无效、过期、已使用或用户已停用时返回失败，不返回手机号和用户昵称。

建议错误码：`INVALID_CLIENT`、`TICKET_INVALID`、`TICKET_EXPIRED`、`TICKET_ALREADY_USED`、`USER_DISABLED`、`INTERNAL_ERROR`。
