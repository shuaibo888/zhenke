# 全平台通用券与积分兑换实现说明

> 日期：2026-08-11

## 1. 本次目标

在现有“指定适用商家优惠券”之外新增平台级全平台通用券，并打通管理员创建与定向下发、用户积分兑换、下单使用及积分流水展示。

用户端“我的积分”页面调整为积分概览与可兑换优惠券页面；原积分变更记录迁移到独立页面，入口位于积分概览卡片右上角。

## 2. 固定业务规则

### 2.1 优惠券范围

- `MERCHANT_SPECIFIC`：现有指定商家券。管理员券可指定多个有效商家；商家券的适用范围由服务端固定为当前商家。
- `PLATFORM_WIDE`：全平台通用券，不保存 `shop_coupon_merchant` 适用商家记录，可用于任一正常营业商家。
- 全平台通用券固定为无门槛券，`minimum_spend` 由服务端强制保存为 `0.00`，管理端不展示最低消费金额输入项。
- 历史优惠券统一保持 `MERCHANT_SPECIFIC`，不改变现有券的使用范围。
- 多商家购物车仍拆分为多个商家订单；优惠券只用于单商家结算，“全平台通用”表示可选择任一商家使用，不表示一张券同时抵扣多个拆分订单。

### 2.2 结算叠加规则

- 同一笔单商家订单可以选择多张用户优惠券，不限制只能使用一张。
- 指定商家券可以与全平台通用券混合使用，也允许多张全平台通用券同时使用。
- 每张指定商家券的最低消费门槛都按优惠前商品合计判断，不因前一张券已经抵扣而改变资格。
- 服务端逐张校验当前用户归属、未使用状态、主券上下架状态、有效期、适用商家和最低消费门槛，并使用固定顺序加锁，防止重复核销和并发死锁。
- 订单优惠金额为所选券面额之和与商品合计的较小值，实付金额最低为 `0.00`，不得出现负数。
- 券面额允许大于或等于商品金额；当已选券已经把订单抵扣到 `0.00` 后，不再核销没有产生实际抵扣的多余券。
- 券面额可以大于商品金额。例如 2 元商品使用 3 元无门槛通用券时，该券被核销，订单优惠 2 元、实付 0 元。
- 多券可叠加。例如 10 元商品使用三张 3 元通用券，优惠 9 元、实付 1 元；再如 10 元商品使用 5 元指定商家券和 3 元通用券，优惠 8 元、实付 2 元。
- 实付为 0 的订单由服务端直接进入 `PAID`，支付渠道记为 `COUPON`，不创建微信支付单。
- 待付款订单取消或超时取消时，按 `used_order_id` 一次返还该订单使用的全部优惠券。

### 2.3 权限

- 只有平台管理员可以创建、编辑、上下架和定向下发 `PLATFORM_WIDE` 优惠券。
- 商家列表、详情、编辑、上下架和下发接口只能访问 `owner_merchant_id` 为当前商家的优惠券，因此不能看到或操作平台通用券。
- 商家创建接口拒绝客户端伪造的 `PLATFORM_WIDE` 类型或积分兑换价格。

### 2.4 积分兑换

- 平台通用券必须设置大于 0 的积分兑换价格；指定商家券不能设置积分兑换价格。
- 用户只能使用当前登录商城账号的积分，接口不接受客户端用户 ID、余额或兑换价格。
- 只展示已上架、已生效、未过期且配置兑换价格的平台通用券。
- 每位用户对同一张平台通用券最多兑换一次。
- 兑换时服务端锁定优惠券和积分账户，并在同一事务内完成：资格校验、库存占用、积分扣减、累计消费增加、成功积分流水、优惠券下发和兑换审计。
- 积分不足、库存不足、优惠券状态变化或重复兑换时整笔事务失败，不扣积分、不发券。
- 兑换成功后生成的优惠券进入现有“我的优惠券”与结算链路；取消待付款订单时仍按现有规则返还优惠券使用状态。

## 3. 数据与接口

### 3.1 数据库

- `shop_coupon.scope_type`：`MERCHANT_SPECIFIC / PLATFORM_WIDE`。
- `shop_coupon.points_cost`：平台通用券积分兑换价格，指定商家券为空。
- `shop_coupon_exchange`：记录用户兑换、实际扣减积分和兑换时间；唯一约束为 `coupon_id + shop_user_id`。
- 积分消费继续写入现有 `shop_user_point_account` 与 `shop_user_point_record`，来源系统使用 `MALL`，业务类型使用 `CONSUME`。
- `shop_order_coupon`：逐张记录订单使用的用户券、券主数据、券面额和该券在本单实际抵扣金额，是多券订单的审计明细。
- 每张已实际参与抵扣的用户券仍写入 `shop_user_coupon.used_order_id`；旧的 `shop_order.user_coupon_id` 单券字段直接删除，订单用券统一以明细表为准。

### 3.2 用户接口

- `GET /shop/users/me/points/coupons`：查询当前可展示的积分兑换通用券。
- `POST /shop/users/me/points/coupons/{couponId}/exchange`：当前用户兑换指定通用券。
- `GET /shop/users/me/points/records`：保留原分页积分流水接口，由新积分明细页面使用。

## 4. 页面调整

- 管理/商家后台共用优惠券模块：管理员可选择“指定商家券 / 全平台通用券”；商家端不出现通用券类型和积分兑换字段。
- 管理员选择全平台通用券时隐藏适用商家选择，显示积分兑换价格。
- 管理员选择全平台通用券时同时隐藏最低消费金额，提交与服务端都固定为 `0.00`。
- 用户结算页优惠券改为多选，实时汇总选中数量、优惠金额和最低实付金额，支持指定商家券与平台券混选。
- 当新选中的优惠券会首次把本单抵扣到 `0.00` 时，页面弹出醒目确认，明确展示该券面额、本单实际抵扣额、订单无需微信支付且该券会被正常核销；订单已经为 `0.00` 后继续选择优惠券会被直接拦截。
- 用户积分首页：保留当前积分、累计划入、累计消费；增加可兑换优惠券列表和兑换按钮。
- 积分概览卡片右上角增加“积分明细”按钮，跳转 `/profile/point-records`。
- `/profile/point-records` 独立展示原积分变更记录与分页。

## 5. 上线边界

- 新数据库脚本必须先在目标数据库执行并核对，再发布包含新字段查询的后端。
- 本轮新增 `shop_order_coupon` 并删除 `shop_order.user_coupon_id`；对应一次性迁移已由用户在目标数据库执行，SQL 文件按用户要求删除且不纳入源码提交。仍不生成演示积分、不替用户兑换优惠券。
- 后续正式多租户改造时，优惠券范围、兑换唯一约束和积分流水幂等键需要加入可信 `tenant_id`。
